## Command Breakdown

**`git log`** - Shows the commit history/logs

**`--follow`** - **Crucially important**: Follows the file through renames and moves. Without this, if a file was renamed, git would lose track of its history.

**`--`** - This separator tells git that everything after it is a file path (not command options)

**`.cursor/rules/broz/workflows/task/new.mdc`** - The specific file path to check history for

## What it does

This command shows **all commits that affected this specific file**, including:
- When it was first created/added
- Every modification made to it  
- When it was deleted (like in our case)

## Why we used it

When you suspected the file was deleted, this command revealed that:
1. The file existed in the commit `355960a69548312bc5789ae3d13d1f7f61edeb09` from Dec 13
2. It was still there in commit `3b87535c48674f7702228cff6078190fc31c2237` from Dec 16
3. It got deleted sometime after Dec 16

Without `--follow`, if the file had ever been renamed, we'd lose its history. The `--` separator ensures git treats the path as a literal file path, not as command options.

## Common variations

- `git log --oneline -- .cursor/rules/broz/workflows/task/new.mdc` - Shows compact one-line summaries
- `git log -p -- .cursor/rules/broz/workflows/task/new.mdc` - Shows the actual diff/patch changes for each commit
- `git log --since="1 week ago" -- .cursor/rules/broz/workflows/task/new.mdc` - Shows only recent changes

This is a powerful forensic tool for tracking down what happened to specific files in your repository! 🔍
