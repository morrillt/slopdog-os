**Examining the Core Difference**

Now, I'm focusing on the significant distinctions between rules and commands. The key is in how these approaches alter my long-term behavior. Rules are persistent, injected directly into the context, and influence the overall persona and operating constraints. I'm contrasting this with commands, which are better suited for individual tasks or immediate actions.


**Articulating the Rationale**

I'm now clarifying the reasons behind using rules instead of commands for the modes and menu functionality. My focus is on the crucial difference in context injection: rules shape long-term persona and constraints, while commands handle individual tasks. Rules also support the "kernel" concept, functioning as dispatchers, which is aligned with the user's affinity for menus with handlers.



I chose **Rules** (`.cursor/rules/*.mdc`) instead of **Commands** (`.cursor/commands/`) for the Modes and Menu because of how Cursor processes them:

1.  **Rules Define "Who I Am" (Context & Behavior)**
    *   **Modes are Personas**: When you are in `PLAN` mode, you want me to *behave* like a Product Manager (ask questions, write docs, don't code). When in `BUILD` mode, you want me to be a Developer (write code, run tests).
    *   **Automatic Injection**: Rules are "injected" into my system instructions when triggered. This means I "remember" the rules of the mode for the entire conversation turn.
    *   **Commands are "One-Offs"**: Commands are typically better for specific actions (e.g., "Generate a Unit Test", "Fix Linting") rather than setting a persistent operating mode.

2.  **The "Menu" Logic (Dispatcher)**
    *   The `00-bmad-kernel.mdc` rule acts as the "Menu." It sees your current context (from the YAML file) and automatically "loads" the correct instructions.
    *   If we used Commands, you might have to manually type `/plan` or `/build` every time you wanted to reinforce the mode. With Rules, if the `project-context.yaml` says `mode: plan`, the Plan Rule is automatically active.

**Summary**:
*   **Rules**: "Behave like this." (Perfect for Modes)
*   **Commands**: "Do this specific thing." (Good for individual steps)
