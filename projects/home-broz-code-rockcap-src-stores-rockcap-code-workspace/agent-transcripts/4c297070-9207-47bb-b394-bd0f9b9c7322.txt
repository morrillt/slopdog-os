## Overview

This document introduces the **Opening Range Breakout (ORB)** trading concept, explains how **Average True Range (ATR)** is used in our implementation, and details the specific parameters we're backtesting in our **ORB-R (ORB Retest Breakout)** strategy.

## What is Opening Range Breakout (ORB)?

**Opening Range Breakout** is a trading strategy that identifies the high and low price range during the first few minutes of the trading day (the "opening range"), then trades breakouts when price moves beyond this range.

### Core Concept

1. **Define the Opening Range**: During the first N minutes (e.g., 9:30-9:35 AM ET), identify the highest high and lowest low.
2. **Wait for Breakout**: Monitor price action. When price breaks above the range high (long signal) or below the range low (short signal), a trade opportunity exists.
3. **Enter on Confirmation**: Enter the trade after confirming the breakout isn't a false signal.

### Why ORB Works

- The opening minutes often establish the day's trading range
- Breakouts from this range can indicate strong directional momentum
- Early morning volatility provides trading opportunities
- The range acts as a natural support/resistance level

---

## What is Average True Range (ATR)?

**Average True Range** is a technical indicator that measures market volatility by calculating the average of true ranges over a specified period.

### How ATR is Calculated

For each candle, the **True Range** is the maximum of:
1. Current high - current low
2. Absolute value of (current high - previous close)
3. Absolute value of (current low - previous close)

The **ATR** is then the average of these True Range values over N periods (typically 14 candles).

### Why ATR Matters

- **Volatility Measurement**: Higher ATR = more volatile market
- **Dynamic Adjustments**: Allows stop losses and entry buffers to adapt to current market conditions
- **Risk Management**: Helps size positions and set stops based on actual market movement, not fixed point values

### Our ATR Implementation

We calculate ATR using a rolling window:
- **Default Period**: 14 candles
- **Default Multiplier**: 2.0 (used for stop loss distances)
- **Dynamic Calculation**: ATR is recalculated at each candle to reflect current volatility

```typescript
// Example: ATR-based breakout buffer
const currentAtr = getAtrAtCandleIndex(candles, 14, candleIndex);
const breakoutBuffer = currentAtr * 0.25; // 25% of ATR as buffer
```

## Our Implementation: ORB-R (ORB Retest Breakout)

Our **ORB-R** strategy combines Opening Range Breakout with retest confirmation to reduce false breakouts.

### Strategy Flow

1. **Define Opening Range**: Calculate high/low from first N minutes
2. **Wait for Breakout**: Price breaks beyond range ± ATR buffer
3. **Confirm Breakout**: Require candle close beyond breakout level (or two consecutive closes)
4. **Optional Retest**: Wait for price to retest the breakout level (filters chop)
5. **Enter Trade**: Enter when trigger level is crossed after confirmation
6. **Manage Exit**: Use fixed profit target and stop loss, or let trade run to cutoff time

### Key Features

- **ATR-Based Breakout Buffer**: Requires breakout to exceed range by a percentage of ATR (reduces false signals)
- **Confirmation Modes**: Single close or two consecutive closes beyond breakout level
- **Retest Requirement**: Optional wait for price to retest breakout level before entry
- **Chop Filtering**: Designed to avoid false breakouts in choppy markets
- **Time-Based Cutoff**: Stops trading after a specified time (default: 9:45 AM ET)

## Parameters We're Backtesting

We're systematically testing multiple parameter combinations to find optimal settings. Here's what we're varying and why:

### ORB-Specific Parameters

#### 1. **Opening Range Window** (`orbWindowMinutes`)
- **Values**: `[2, 5, 10]` minutes
- **Why**: Tests different opening range definitions
  - **2 minutes**: Very tight range, more breakouts but potentially more false signals
  - **5 minutes**: Standard range, balanced approach
  - **10 minutes**: Wider range, fewer but potentially stronger signals

#### 2. **Breakout Buffer** (`breakoutBufferAtr`)
- **Values**: `[0.0, 0.25, 0.5]` (as multiples of ATR)
- **Why**: Tests how much buffer is needed to filter false breakouts
  - **0.0**: No buffer, pure breakout (more signals, higher false rate)
  - **0.25**: Small buffer (25% of ATR) - moderate filtering
  - **0.5**: Larger buffer (50% of ATR) - stronger confirmation required

#### 3. **Confirmation Mode** (`confirmationMode`)
- **Values**: `["close", "two_closes"]`
- **Why**: Tests confirmation strength
  - **"close"**: Single candle close beyond breakout level (faster entry)
  - **"two_closes"**: Two consecutive closes beyond breakout (stronger confirmation, fewer signals)

#### 4. **Retest Requirement** (`requireRetest`)
- **Values**: `[true, false]`
- **Why**: Tests whether retest filtering improves results
  - **true**: Wait for price to retest breakout level before entry (filters chop)
  - **false**: Enter immediately after confirmation (faster entry, potentially more false signals)

#### 5. **Retest Timeout** (`retestTimeoutMinutes`)
- **Values**: `3` minutes (fixed in current tests)
- **Why**: Maximum time to wait for retest before giving up on signal

#### 6. **Avoid First Minutes** (`avoidFirstMinutes`)
- **Values**: `[0, 5]` minutes (conditional on retest requirement)
- **Why**: Avoids entries immediately after opening range window
  - **0**: No avoidance period
  - **5**: Skip first 5 minutes after ORB window (allows market to settle)

### Standard Trading Parameters

These are tested across all strategies:

#### 7. **Trigger Points** (`triggerPts`)
- **What**: Points above/below start price to trigger entry
- **Why**: Determines entry sensitivity and trade frequency

#### 8. **Profit Target Points** (`profitTargetPts`)
- **What**: Points from start price to take profit
- **Why**: Defines reward target for each trade

#### 9. **Stop Loss Points** (`stopLossPts`)
- **What**: Points from trigger to stop loss
- **Why**: Defines risk per trade

#### 10. **Max Round Trips** (`maxRoundTrips`)
- **Values**: `[1, 2, 3]`
- **Why**: Tests whether multiple trades per day improve results
  - **1**: Single trade per day (conservative)
  - **2-3**: Multiple trades if re-entry conditions met (more opportunities)

#### 11. **Cutoff Time** (`cutoffTime`)
- **Values**: `["09:40", "09:45", "10:00"]`
- **Why**: Tests optimal trading window
  - Earlier cutoff: Focuses on highest volatility period
  - Later cutoff: More opportunities but potentially lower quality

### ATR Parameters

#### 12. **ATR Period** (`atrParams.period`)
- **Default**: `14` candles
- **Why**: Standard ATR calculation period (not currently varied in tests)

#### 13. **ATR Multiplier** (`atrParams.multiplier`)
- **Default**: `2.0`
- **Why**: Used for stop loss distance calculations (not currently varied in ORB-R tests)

- **Too Short (2 min)**: More signals but potentially more noise
- **Too Long (10 min)**: Fewer signals, may miss early momentum
- **Sweet Spot**: Likely 5 minutes for balanced approach

### Breakout Buffer

- **Large Buffer (0.5)**: Strong confirmation but may miss valid breakouts
- **Sweet Spot**: Likely 0.25 ATR for balance

### Retest Requirement
- **With Retest**: Filters chop, reduces false breakouts, but may miss fast moves
- **Without Retest**: Faster entries, catches momentum, but more false signals
- **Sweet Spot**: Depends on market conditions (choppy vs. trending)

### Confirmation Mode
- **Single Close**: Faster entry, more trades
- **Two Closes**: Stronger confirmation, fewer but potentially higher quality trades

## Running Backtests

```bash
# Set standard trading parameters
```

- **ORB Window**: `[2, 5, 10]` minutes (hardcoded in script)

- **Require Retest**: `[true, false]` (hardcoded)

+## Concerns / Known Issues (Current Implementation)
+
+These are the main places where the **current** ORB-R implementation can produce misleading results or behave differently than “classic ORB” expectations.
+
+- **Time units vs candle resolution**:
+  - Several “minutes” params are treated as **candle counts** (`orbWindowMinutes`, `avoidFirstMinutes`, `retestTimeoutMinutes`).
+  - If your dataset is **1-second candles**, `orbWindowMinutes: 5` effectively becomes **5 seconds**, not 5 minutes. Same issue for retest/avoid windows.
+
+- **`confirmationMode: "close"` is not actually a close-confirmation**:
+  - Breakout detection is based on `candle.high` / `candle.low` crossing the breakout threshold.
+  - Only `"two_closes"` checks the **next candle close** for confirmation.
+
+- **ATR “fallback” early in the day is dimensionally wrong**:
+  - When there aren’t enough candles to compute ATR, the strategy uses the **ATR period number** as a price-sized ATR surrogate.
+  - That can create an artificial breakout buffer (e.g., `14 * 0.25 = 3.5 points`) that may have nothing to do with actual volatility.
+
+- **ORB logic gates entries, but entries/exits are still driven by global fixed triggers**:
+  - After ORB breakout/retest, entry is still based on `startPrice ± triggerPts` (global triggers), not the ORB level itself.
+  - TP is `startPrice ± profitTargetPts` and SL is `trigger ± stopLossPts`, which can diverge from ORB-centric stop/target models (e.g., stop on “other side of range”).
+
+- **Parameters surfaced in docs vs what’s actually wired today**:
+  - `stopLossByProfitThreshold` is accepted/logged but not applied in ORB-R logic.
+  - `atrParams.multiplier` is validated/logged but not used for ORB-R decisions (buffer uses ATR * `breakoutBufferAtr`).
+
+- **Retest definition is coarse**:
+  - Retest checks only whether price touches the raw ORB boundary (`orbHigh` / `orbLow`), not a band (e.g., within X ticks) and not the buffered breakout level.
+  - This can label very noisy “touches” as retests.

Classic ORB entries are usually anchored to the ORB level (breakout level / retest level). But here:
- ORB decides **when you’re allowed to start looking for entries**
- The entry itself is still “old system”: **startPrice ± triggerPts**

- ORB breakout happens, but **price never hits `startPrice + triggerPts`**, so no trade.
- ORB breakout is long, but later **the short trigger gets hit first**, and the code can flip `direction` at entry time (see snippet above). That undermines the idea of ORB determining direction.

- **ORB-only entry**: enter at breakout (or retest completion) near the ORB level, and drop `startPrice ± triggerPts`.
- **Trigger-only strategy**: drop ORB gating entirely.
