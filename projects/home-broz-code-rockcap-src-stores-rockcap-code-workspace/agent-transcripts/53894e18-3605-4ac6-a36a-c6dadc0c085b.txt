Usage for `scripts/analyzer/analyze-permutations.js` with a settings JSON file:

## Basic Usage with Settings File

```bash
node scripts/analyzer/analyze-permutations.js --settings path/to/settings.json
```

Or using the alias:
```bash
node scripts/analyzer/analyze-permutations.js --settings-file path/to/settings.json
```

## Settings File Format

The script accepts two formats:

1. **Flat format** (input settings):
```json
{
  "tpLevels": [30, 80, 100],
  "slMargins": [7, 8],
  "triggerMargins": [5, 7],
  "maxRoundTrips": [2, 3],
  "cutoffTimes": ["09:45"],
  "steppedSLConfigs": [null, {"20": 2, "25": 10}],
  "startDay": "2022-01-03",
  "endDay": "2025-12-31"
}
```

2. **Nested format** (from previous run's `settings.json`):
```json
{
  "config": {
    "tpLevels": [30, 80, 100],
    "slMargins": [7, 8],
    ...
  }
}
```

The script detects both formats and extracts the config accordingly.

## Notes

- The path can be relative to the project root or absolute
- Settings from the file override environment variables and defaults
- The script supports JSON comments (lines starting with `//`) which are stripped before parsing
- If you're in the `Next settings` folder, you could run:
  ```bash
  node scripts/analyzer/analyze-permutations.js --settings "data/pipeline/4yearpipe1s/stage2 - analysisResults/Next settings/4 year max settings.json"
  ```

## Key learnings

1. **The “Great Month” winners were regime-specific.** Over 498 trading days, TP=200/150 become structurally bad.
2. **TP=100 is the only survivable TP in long-horizon runs (in this dataset).**
3. **Stepped SL is not optional.** Without it, you enter a blow-up basin.
4. **MaxRT=2 beats MaxRT=3/4** over long horizons (opposite of the 24‑day narrative).
5. **ORB retest requirement is a tax.** `requireRetest=true` loses edge.
6. **Most of the “profitability” signal comes from non-ORB knobs** (TP/steppedSL/RT/trigger). ORB tweaks are second-order once you prune the obvious losers.
