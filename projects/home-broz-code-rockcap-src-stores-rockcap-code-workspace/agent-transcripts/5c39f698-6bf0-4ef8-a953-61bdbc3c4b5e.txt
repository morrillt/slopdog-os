/**
 * Prompt user for date range (start day and end day) with validation.
 * 
 * @param {string|null} defaultStartDay - Default start day (YYYY-MM-DD) or null
 * @param {string|null} defaultEndDay - Default end day (YYYY-MM-DD) or null
 * @returns {Promise<{startDay: string|null, endDay: string|null}>}
 */
function promptForDateRange(defaultStartDay = null, defaultEndDay = null) {
  return new Promise((resolve) => {
    const rl = readline.createInterface({
      input: process.stdin,
      output: process.stdout,
    });

    const datePattern = /^\d{4}-\d{2}-\d{2}$/;

    function promptStartDay() {
      const defaultText = defaultStartDay ? ` (default: ${defaultStartDay})` : " (or press Enter for no filter)";
      rl.question(`Start day (YYYY-MM-DD)${defaultText}: `, (answer) => {
        const trimmed = answer.trim();
        let startDay = null;

        if (!trimmed) {
          startDay = defaultStartDay;
        } else {
          if (!datePattern.test(trimmed)) {
            console.error(`Invalid format: "${trimmed}". Must be YYYY-MM-DD (e.g., 2025-11-27)`);
            promptStartDay();
            return;
          }
          startDay = trimmed;
        }

        promptEndDay(startDay);
      });
    }

    function promptEndDay(startDay) {
      const defaultText = defaultEndDay ? ` (default: ${defaultEndDay})` : " (or press Enter for no filter)";
      rl.question(`End day (YYYY-MM-DD)${defaultText}: `, (answer) => {
        const trimmed = answer.trim();
        let endDay = null;

        if (!trimmed) {
          endDay = defaultEndDay;
        } else {
          if (!datePattern.test(trimmed)) {
            console.error(`Invalid format: "${trimmed}". Must be YYYY-MM-DD (e.g., 2025-11-28)`);
            promptEndDay(startDay);
            return;
          }
          endDay = trimmed;
        }

        // Validate range
        if (startDay && endDay && startDay > endDay) {
          console.error(`Invalid range: start day (${startDay}) must be <= end day (${endDay})`);
          promptEndDay(startDay);
          return;
        }

        rl.close();
        resolve({ startDay, endDay });
      });
    }

    promptStartDay();
  });
}

  contents: # IMPROTANT: ORB strategy naming, gap-aware entries, analyzer output

This note exists to prevent future refactors from accidentally undoing key assumptions in the ORB family.

## ORB strategy display names

- The Strategy `name` for ORB variants should **start with `ORB`**.
- Rationale: makes it easy to find/filter in UI menus and analysis output.
- The Strategy `id` can remain specific/stable (e.g. `orb-retest-breakout-v2`).

## Gap-aware entry (no time-machine fills)

For ORB strategies that enter based on a trigger level, if scanning begins *after* a lockout/hold period (or after a retest gate) and the candle opens beyond the trigger, we must not assume a fill at the historical trigger price.

Implementation pattern (pre-slippage levels):
- Long: `entryLevel = max(trigger, candle.open)`
- Short: `entryLevel = min(trigger, candle.open)`

Then apply slippage in the normal direction-specific way.

## Intrabar same-candle resolution must match actual entry level

When using `resolveIntrabarDirectional(...)` for same-candle entry+exit ambiguity, ensure that `entryLevel` passed to the resolver matches the entry model actually used by the strategy.

- If the strategy uses gap-aware entry, the resolver must use the **gap-adjusted entryLevel**, not the original trigger.
- Otherwise, same-candle SL/TP outcomes can become inconsistent.

## Permutation analyzer output layout

The permutation analyzer scripts write each run into a dedicated folder under:
- `data/pipeline/4yearpipe1s/stage2 - analysisResults/`

Each run folder contains:
- `settings.json` – full run configuration + resolved date range
- `results.csv` – results only (no frontmatter)

Folder name pattern:
- `<strategyIdsJoined>_<MMDD_HHMM>_<X>days`

## ORB parameter grid in analyzer

When running ORB strategies, the analyzer may optionally expand the permutation space using an ORB-specific parameter grid (ORB window, breakout buffer, confirmation modes, retest modes, entry models).

Be careful: enabling this grid multiplies total permutations significantly.
