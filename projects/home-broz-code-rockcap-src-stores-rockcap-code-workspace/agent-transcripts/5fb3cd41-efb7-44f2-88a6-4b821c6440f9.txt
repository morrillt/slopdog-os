### How to tell “type/interface” vs “function/object” in TS imports

In TypeScript there are **two namespaces** a name can live in:

- **Type namespace** (erased at runtime): `type`, `interface`, type aliases, etc.
- **Value namespace** (exists at runtime): `function`, `const`, `class`, `enum` (regular enums), objects, etc.

So, “what is this import?” depends on **how it’s exported** *and* **how it’s imported**.

### The fastest rules of thumb

- **If you see `import type { X } ...`** then `X` is **definitely type-only** (could be `type` alias or `interface` or other type). It will not exist at runtime.
- **If you see `import { X } ...` (no `type`)** then `X` is a **runtime value import** (function/const/class/etc).  
  - Caveat: TS *allows* importing types this way too, but if `X` is only a type, TS can erase it depending on your TS config. In practice: if the module really exports only a type named `X`, you should import it with `import type`.
- **To know exactly what it is**: jump to where it’s exported and look for `export type`, `export interface` (type-only) vs `export function`, `export const`, `export class` (runtime value).
